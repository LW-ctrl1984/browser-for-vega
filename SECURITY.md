# Security Policy

## Reporting a vulnerability

Please avoid publishing sensitive security details in a public issue before the maintainer has had a reasonable opportunity to review them.

If private security-reporting functionality is enabled for this repository, prefer that channel. Otherwise, open a minimal public issue asking for a private contact method without including exploit details, credentials, personal data, or secrets.

## Scope

Examples of useful reports include:

- unintended exposure of browsing data or credentials
- insecure storage of secrets
- dangerous URL handling
- command or code injection
- sandbox or permission-boundary issues
- update/package integrity problems

## Responsible testing

Do not test vulnerabilities against systems, accounts, websites, or services you do not own or have permission to test.
